Network · Chapter 03

第 3 章 · 关键协议

Core Protocols

网络世界有几百种协议，但你天天在用的只有六七个——HTTP、TCP、UDP、DNS、IP，加上几个"配角"（ARP、ICMP、DHCP）。这一章把这六个"主角"讲透，你就掌握了互联网 80% 的底层逻辑。

生活场景
📬 寄快递 vs 打电话 vs 查电话簿

协议不是抽象概念——它对应你每天都在做的事：

· HTTP = 寄快递（有单号、有回执、能追踪）
· TCP = 打电话（先拨号、确认接通、再说话、说完挂断）
· UDP = 大喇叭广播（喊一嗓子，听没听到随它去）
· DNS = 查电话簿（知道名字，查号码）
· IP = 邮政编码（决定包裹送到哪个城市）
· ARP = 小区门卫（知道门牌号，找具体哪一户）

本章要回答什么

协议这个词听着玄，说白了就是双方事先约好的规矩——先说什么、后说什么、说错了怎么办。就像两个人打电话，得先有"喂"这一声确认对方在听，才好开始说正事。这一章要回答六个问题：

  • 你打开一个网页，浏览器到底对服务器说了什么？——HTTP 的请求与回应，以及那些 404、500 是什么意思。
  • 凭什么保证数据不丢、不乱、不重？——TCP 的三次握手、编号确认、丢了重发。
  • 为什么看直播打游戏偏偏不要这份"保证"？——UDP 的取舍：宁可丢一帧，不要卡一秒。
  • 你只输入了 baidu.com，机器怎么知道去哪找？——DNS 这本"互联网电话簿"怎么查。
  • 数据包跨越几千公里，靠什么认路？——IP 地址与路由，以及家里那个 192.168 开头的地址是怎么回事。
  • 还有哪些默默干活的配角？——ARP、ICMP、DHCP，你 ping 一下、连个 WiFi 就自动用上了。
把协议想成"办事的规矩"
去银行办事，你得先取号（建立连接），柜员叫号你才上前（确认对方就绪），递材料时对方会核对齐不齐（校验），材料不全会退回让你补（重传），办完了双方签字确认离场（断开连接）。

这一整套流程，就是银行的"协议"。它不是为了麻烦你，而是为了在柜员不认识你、你也不认识柜员的前提下，把事情办得清楚、可追溯、出错能补救。

网络协议干的活儿一模一样——两台从没见过面的机器，隔着几千公里，靠一套事先写死的规矩，把一堆 0 和 1 准确送到对面。规矩越死，出错时越好查；规矩越松，跑得越快但越容易乱。这就是 TCP 和 UDP 的分别，也是这一章反复出现的主题。

本章的六节

§ 3.1

HTTP / HTTPS

浏览网页的协议——请求/响应、状态码、Cookie、加密。
§ 3.2

TCP

可靠传输的协议——三次握手、四次挥手、流量控制。
§ 3.3

UDP

快速但不保证的协议——视频、直播、游戏为什么用它。
§ 3.4

DNS

域名翻译成 IP——递归查询、缓存、污染与 DoH。
§ 3.5

IP

网络层的核心——IPv4/IPv6、子网、NAT、路由。
§ 3.6

其他重要协议

ARP、ICMP、DHCP、SSH、FTP、SMTP——配角也关键。
Recap · 收束

协议是网络的"共同语言"。六个主角各司其职：HTTP 管内容、TCP 管可靠、UDP 管速度、DNS 管翻译、IP 管地址、ARP 管本地。理解它们，你就理解了数据怎么从一台机器流到另一台机器。
