## 核心开发规范（每次必须遵守）

### 0. 三级命名规范（篇 → 章 → 节）★ 最重要

全站严格遵守 **篇 → 章 → 节** 三级结构，**最小单位是"节"，不是"篇"**。

| 层级 | 命名格式 | 示例 | 对应文件 |
|---|---|---|---|
| **篇**（顶层分支） | `XX篇` | 智能篇 / 网络篇 / 界面篇 / 电学篇 | 无独立页面，只是树上的分支 |
| **章**（第二层） | `第 X 章 · 名字`（**不带"篇"字**） | 第 5 章 · 神经网络 | `05-neural-network.html`（章总览页） |
| **节**（第三层） | `§ X.Y · 名字`（**不带"节"或"篇"字**） | § 5.1 · 神经元 | `05-1-neuron.html`（节正文页） |

**禁止事项**:
- ❌ 章级标题写成"第 5 章 · 神经网络**篇**"
- ❌ 节级标题写成"§ 5.1 · 神经元**篇**"或"§ 5.1 · 神经元**节**"
- ❌ 主页卡片 `<h3>` 写成"神经网络**篇**"
- ❌ 章总览页写"本章的六个**子篇**"（应写"本章的六**节**"）

**页面内标记**:
- 节页面 `chapter-head` 的 num 用 `§ X.Y · Section`（不是 `Sub-chapter`）
- 章页面 `chapter-head` 的 num 用 `Chapter · XX`
- 章总览页导航区标题用"本章的 X 节"

### 1. 章节结构规范

每个"章"和每个"节"都必须是一个**独立 HTML 页面**，放在 `chapters/<篇目录>/` 下。

**页面命名规则**:
- 章总览页: `XX-<title>.html` (如 `04-machine-learning.html`)
- 节正文页: `XX-Y-<title>.html` (如 `04-1-supervised.html`)

**每个页面必须包含**:
```html
<!DOCTYPE html>
<html lang="zh-CN">
<head>
  <meta charset="UTF-8">
  <meta name="viewport" content="width=device-width, initial-scale=1.0">
  <title>§ X.Y · 标题 · 学海无涯</title>
  <link rel="stylesheet" href="../../_shared/css/theme.css">
  <!-- 用到互动组件时才加这一行 -->
  <link rel="stylesheet" href="../../_shared/css/interactive.css">
</head>
<body>
<article class="page">
  <!-- 顶部面包屑 -->
  <nav class="topbar">...</nav>
  <!-- 章节头：num 用 "§ X.Y · Section" 或 "Chapter · XX" -->
  <header class="chapter-head">...</header>
  <!-- 内容（含互动组件 div.lab） -->
  ...
  <!-- 底部翻页（.pager）：节用"上一节/下一节"，跨章用"上一章/下一章" -->
  <div class="pager">
    <a class="btn prev" href="...">← 上一节</a>
    <a class="home" href="../../index.html">☰ 主页</a>
    <a class="btn next" href="...">下一节 →</a>
  </div>
  <!-- 页脚格式：学海无涯 · <篇名> · § X.Y -->
  <div class="page-foot">学海无涯 · 界面篇 · § X.Y</div>
</article>
<!-- 用到互动组件时才加这一行，且必须在 float-pager 之前 -->
<script src="../../_shared/js/interactive.js"></script>
<!-- 必须引入悬浮翻页脚本 -->
<script src="../../_shared/js/float-pager.js"></script>
</body>
</html>
```

**禁止内联 `<style>`**——所有样式都放 `theme.css` / `interactive.css`，页面里不许写 `<style>` 块。

### 2. 悬浮翻页岛规范（重要）

**每个章节页面底部必须有 `.pager`**，并引入 `float-pager.js`。

**float-pager.js 会自动**:
- 克隆 `.pager` → 创建 `.pager-float`（悬浮岛）
- 给 body 加 `has-float-pager` 类（底部留白）

**悬浮岛样式**:
- 磨砂玻璃: `rgba(255,255,255,0.55)` + `backdrop-filter: blur(20px)`
- 圆角胶囊: `border-radius: 999px`
- 居中悬浮: `position: fixed; bottom: 18px; left: 50%; transform: translateX(-50%)`

**检查清单**（每次新建页面后）:
- [ ] 页面有 `.pager` 元素
- [ ] 页面引入了 `../../_shared/js/float-pager.js`
- [ ] 浏览器测试：滚动时悬浮岛始终可见

### 3. 认知知识树规范（当前实现 · SVG 自绘）

**数据位置**: `assets/tree-data.js` → `window.__cognitionTreeData`

**节点数据结构**（严格按 COGNITION_TREE_FORMAT_SPEC）:
```javascript
{
  id: "唯一稳定英文ID",        // 必填
  label: "节点显示名称",        // 必填
  desc: "节点简要说明",         // 必填
  words: "3200 字",            // 必填：内容字数（不再用"建议时间"）
  children: [],                // 必填（叶子节点空数组）
  href: "chapters/xxx.html",   // 可选：跳转链接
  color: "#4a6d8c"             // 可选：仅顶层分支设置，后代继承
}
```

**`words` 字段规范**（★ 已废弃"建议时间"）:
- **节节点** → 该节实际中文字数，如 `'3200 字'`；未上线的写 `'待撰写'`
- **章节点** → 该章所有节 + 总览页字数合计，如 `'约 1.8 万字'`
- **篇节点** → 该篇合计，如 `'约 6 万字'`
- 根节点 → 全站合计
- **理由**：阅读时间因人而异，字数是客观可核对的事实；也便于直接对照 §6 的 3000 字硬标准

**树结构**:
```
学海无涯 (root)
├── 智能篇 (color: #4a6d8c)
│   └── 第 1-14 章
├── 网络篇 (color: #556b3d)
│   └── 第 1-10 章
├── 界面篇 (color: #8a5a7a)
└── 电学篇 (color: #a0662c)
    └── 第 1-10 章
```

**顶层分支配色**:
- 智能篇 `#4a6d8c`（蓝）· 主页 banner `.vol-banner`
- 网络篇 `#556b3d`（绿）· 主页 banner `.vol-banner.net`
- 界面篇 `#8a5a7a`（紫褐）· 主页 banner `.vol-banner.gui`
- 电学篇 `#a0662c`（铜橙）· 主页 banner `.vol-banner.elec`

**节点规范**:
- ID 全树唯一，只用英文/数字/连字符
- 叶子节点必须有空 `children: []`
- 有内容的节点填 `href`，无内容的不填（视觉自动区分）
- 禁止五级嵌套：最多 4 级（root → 篇 → 章 → 子篇）
- 若子篇章已合并成一篇文章，树上只保留一个链接节点
- 例外：文章有清晰分段时可加锚点 `#section-id`，拆成多个子节点（如简史 5 个时代节点）

**视觉规范**:
- **文字前圆点颜色**（唯一状态标识）：
  - **深绿** `#556b3d` = 可跳转（有 `href`）
  - **浅绿** `#d4e2c8` = 可展开（无 `href` 但有子节点）
  - **浅灰** `#d8d4cb` = 叶子节点
- **不显示** `[+]/[-]` 加号按钮、右侧状态圆点、下划线等其他标识
- 节点卡片：184×54 圆角矩形，磨砂玻璃背景
- 连接线：真实 SVG 三次贝塞尔曲线，`<g class="edges">` 先绘制，`<g class="nodes">` 后绘制
- 三区结构：工具栏 + 树画布（磨砂玻璃）+ 详情面板（磨砂玻璃）

**交互规范**:
- **单击节点** → 若有子节点则展开/收起，同时更新详情面板
- **详情面板"打开完整学习章节"按钮** → 跳转 `href`
- **搜索** → 匹配 label + desc，只展开祖先路径，不展开后代
- **缩放**：滚轮、`＋/−` 按钮，范围 `0.55x ~ 2.5x`
- **拖动**：只在画布空白处拖动，不拖节点
- **展开层级**：Ⅰ 一级 / Ⅱ 二级 / Ⅲ 三级 / ⊟ 收起

**节点宽度滑块**（`#node-width-slider`）:
- 工具栏提供"框宽"滑块，范围 `120px ~ 420px`，默认 `184px`，步长 4
- `NODE_W` 是**可变状态**（不是常量），滑块改它后调 `render()` 重算布局
- `NODE_LABEL_MAX`（文字截断字符数）随宽度线性联动：`(NODE_W - 44) / 8.75`，下限 6 字
- `input` 事件只重绘（拖动流畅）；`change` 事件（松手）才 `fitCanvas()`，避免画面乱跳
- `#node-width-reset`（↺ 按钮）恢复默认 184px

**默认缩放规范**（重要）:
- **`fitCanvas()` 必须让树"正好装下"画布**，不能太小
- 上限 `1.4x`（小树自动放大填充画布），下限 `MIN_SCALE=0.55`
- 留 5% 内边距（`padding = 0.95`），不贴边
- SVG `viewBox` **必须用画布像素尺寸**（`0 0 clientW clientH`），不能用 world 尺寸——否则 SVG 自动缩放会和 `scene transform` 叠加，导致我的 scale 失效
- 初始化时用 `requestAnimationFrame × 2 + setTimeout 200ms 兜底`，确保 SVG 布局完成再计算
- window resize 时自动重新 fit

**索引系统**（初始化时构建）:
```javascript
const nodeIndex = new Map();     // id → node
const parentIndex = new Map();   // id → parent node
const depthIndex = new Map();    // id → depth
const branchIndex = new Map();   // id → 顶层分支节点（含 color）
```

**状态管理**:
```javascript
const collapsedNodes = new Set();  // 唯一的展开状态来源
let selectedNodeId;
let scale, translateX, translateY;
```

**移动端触摸支持**（★ 2026-08-07 补，改交互逻辑时不要退回去）:
- 鼠标事件（`mousedown`/`mousemove`/`mouseup`/`wheel`）**在触摸屏上完全不触发**，必须另绑 `touchstart`/`touchmove`/`touchend`/`touchcancel`
- **CSS 必须配套**：`.tree-canvas { touch-action: none; }`。不设的话浏览器会把单指拖动当成滚页面、双指捏合当成缩放整页，**手势被系统抢走，JS 收不到**
- `zoom(delta, cx, cy)` 支持焦点缩放：给了 `cx`/`cy` 就让该点在缩放前后保持不动（滚轮用鼠标位置，捏合用双指中心）
- 双指缩放**相对起始状态整体计算**（记 `pinch.d` / `pinch.s`，用 `pinch.s * (nd / pinch.d)`），**不要逐帧累乘**否则误差漂移
- 手指按在节点上时**跳过平移逻辑**，否则会吞掉节点的 `click`
- 判断是否点在节点上要用**手写的 `inNode()` 沿 `parentNode` 上溯**，因为 SVG 元素的 `closest()` 在个别旧版移动浏览器不可靠；且 SVG 要用 `getAttribute('class')` 而非 `classList`
- 移动端触摸目标**不小于 40px**（工具栏按钮 `min-height: 40px`）
- 加 `@media (hover: none)` 关掉移动端 hover 粘滞

### 3.5 深浅主题规范（★ 2026-08-07 定稿，已上线）

**最终方案：右上角按钮手动切换，不依赖系统与浏览器。**

**为什么不用 `prefers-color-scheme`（这是走了弯路才想清楚的）**：
用户手机上的「黑色模式」来自浏览器的**强制深色网页**功能。它能反转 CSS 背景，**但反转不了 SVG 的 `fill`** → 知识树节点底被染深、节点文字仍是深墨 `#2b2a26` → 深色字压深色底 → 字完全消失。而且各家浏览器行为不一致，跟它较劲改不干净。

**当前实现（三个文件配合）**：
1. `_shared/js/theme-toggle.js` —— 注入右上角圆形按钮，切换 `<html data-theme="dark">`，选择存 `localStorage`（键名 `xhwy-theme`）跨页面保持；同时同步 `<meta name="theme-color">` 让手机地址栏跟着变色
2. `_shared/css/theme.css` —— `.theme-toggle` 按钮样式 + `[data-theme="dark"]` 深色变量（只覆盖颜色，版式字体一律不动）
3. `assets/cognition-tree.css` —— 知识树独立深色块

**必须遵守**：
1. **每个 HTML 页面都要有** `<meta name="color-scheme" content="only light">`（插在 `viewport` 之后）。`only` 关键字拒绝浏览器强制反转。**新建页面必须带这一行**，并在 body 末尾引 `theme-toggle.js`（放在 `float-pager.js` 之后）。
2. 深色态自己声明 `color-scheme: only dark`，让滚动条等原生控件跟着变深，否则深色页面配浅色滚动条很割裂。
3. 深色规则用 **`[data-theme="dark"]` 属性选择器**，**不要用 `@media (prefers-color-scheme: dark)`** ——后者会让浏览器给无显式 `background` 的元素套深色 UA 样式，在浅色系统下冒出深色块（已踩过这个坑）。
4. 底色用**带暖调的深色而非纯黑**（`#1c1e1b` / `#23261f` / `#282b24`），保留纸感。
5. **无背景的容器必须显式给 `background`**（如 `.tree-canvas` 要写 `background: var(--bg)`），不能依赖 UA 默认值。
6. 首页 `index.html` 样式全在**内联 `<style>`** 里、且**不引用 `theme.css`**，所以按钮样式与深色变量要在首页单独写一份。改主题时容易漏掉首页。

**实测基准值**（深色下知识树，可用于回归验证）：节点文字 `rgb(237,240,230)`、节点底 `rgba(44,48,42,.95)`、画布底 `rgb(28,30,27)`、连线 `rgba(150,165,130,.42)`，对比度约 12:1。

**纯靠变量覆盖不到、必须单独处理的地方**：
- `pre` / `code` 底色与边框
- 表格斑马纹（深色下要反向，用 `rgba(255,255,255,.022)`）
- `mark` / `mark.key` 高亮句（浅色的淡黄底在深色下太刺眼，改低饱和暖底）
- `img` / `svg image` 加 `filter: brightness(.92)` 消除发光感
- **知识树需要独立暗色块**：`.node-bg` / `.node-title` / `.node-meta` / **`.edge`（连线最容易漏，浅底深线在深底同样消失）** / `.spec-dot` / `.branch-dot` / 详情面板全套
- 状态圆点的白描边（`stroke: #ffffff`）在深色节点上很扎眼，改成接近底色的深色描边；「可跳转」的深绿 `#556b3d` 在深底看不出，提亮到 `#93b06f` 一类

### 4. 主页卡片规范

**位置**: `index.html` → `.vol-banner` 下的 `.chapters`

**卡片状态**:
- **已上线**: `class="ch-card ready"`, `<span class="badge">已上线</span>`, `href="./chapters/ai/XX.html"`
- **建设中**: `class="ch-card wip"`, `<span class="badge">建设中</span>`, `href="#"`

**每完成一章，必须**:
1. 把 `wip` 改成 `ready`
2. 把 `badge` 文字从"建设中"改成"已上线"
3. 把 `href="#"` 改成真实链接

### 5. 翻页链规范

**每个页面底部 `.pager` 必须正确链接**，形成一条贯穿全篇的线性阅读路径：

```
章总览 → §X.1 → §X.2 → … → §X.n → 下一章总览 → §(X+1).1 → …
```

**方向文字用词**:
- 同章内节与节之间 → `← 上一节` / `下一节 →`
- 节 → 本章总览 → `← 上一节`，标题写"第 X 章 · 总览"
- 本章最后一节 → 下一章总览 → `下一章 →`，标题写"第 X+1 章 · 章名"

**首尾处理**:
- 每篇第一章总览页的"上一章" → `class="btn prev disabled"`（无 href），标题写"已是本篇首章"
- 最后一个已上线节的"下一节" → `class="btn next disabled"`（无 href），标题写"第 X 章 · 章名（建设中）"

**新增章节时必须回头改前一章末节的 next**——否则阅读链断在那里。

### 6. 内容规范

**每个节正文页必须包含**（缺一不可）:
- `p.lead` — 核心观点（带 `<mark class="key">` 高亮）
- `div.scene` — 生活场景类比（带 emoji，含 `.scene-tag` / `.scene-title` / `.link`）
- **8–20 个 `h3`** + `p` — 正文讲解（越多越细越好，见下方字数要求）
- `div.callout.analogy` — 至少一个譬喻框（承载核心概念的完整生活类比，见 §6.2）
- `ul.keylist` 或 `.table-wrap table` — 结构化信息
- **互动组件** `div.lab` — 见 §6.5，至少一个 `quiz`
- `div.callout` — 结尾 Recap 收束
- `div.pager` — 翻页

**章总览页必须包含**: `p.lead` + "本章要回答什么" + `div.callout.analogy` + `div.cards`（各节导航卡片）+ "学之前先记住这一点" `ul.keylist` + `div.pager`。章总览页**不放互动组件**。

**字数要求（只算中文字符，不含标点数字英文）**:

### 6.2 大白话与生活类比规范（★ 第一准则）

### 7.5 交付前自检规范（★ 每次改完必做）

**★★★ 铁律：派出去的 agent 必须先落盘，再返回。绝不允许成果只存在于回执里（2026-08-08 立，已因此丢失整章核实成果）**

**事故经过**：我同时派了两个核实 agent（第 12 章生态、第 13 章风险），要求它们「只做核实，不要写任何文件」，把结果写在回执里返回。结果第 12 章回执只回来 §12.1 就被截断，**第 13 章回执整份丢失**——那是包含几十条 arXiv 编号、法律判例状态、OWASP 条目的完整核实成果，全部蒸发，只能重做。

**根因不是运气差，是我明知故犯**：本 skill 早在 2026-08-07 就记录了「故障一：agent 回执丢失」这一已知故障，我却仍然把大量不可重建的成果放在回执这个**已知会丢的通道**上。

**从此强制执行**：

| 场景 | 禁止 | 必须 |
|---|---|---|
| 派**核实/调研** agent | ❌ 说「不要写任何文件」 | ✅ 要求它把结果写成 `facts-<章节>.md` 存到**临时工作目录**，回执只写一句「已存至 X，共 N 条」 |
| 派**写作** agent | ❌ 让它攒完一次性输出 | ✅ 先 Write 建骨架，再多次 SearchReplace 追加（每次 3~4 个 h3） |
| agent 回执异常/截断 | ❌ 立刻重派 | ✅ 先查磁盘文件与时间戳判断真实进度，往往只需补尾部 |

**「不要写文件」这句话只在一种情况下才对**：任务产出极短（三五行结论）、且丢了重做成本很低。**只要成果是「重建代价高」的（大量出处链接、编号、原文引句），一律必须落盘。**

落盘位置用**临时工作目录**（不污染用户工作区）：`c:\Users\13459\.trae-cn\work\<session>\facts-*.md`。核实类产物属中间件，不进 git。

**批量操作优先用脚本**——新增/修改多个页面时，写一个临时 Python 脚本放在临时工作目录跑，不要逐个手改。避免高频工具调用触发 `AccountRateLimitExceeded`（HTTP 429）。

**注意**：这条只针对**工具调用频率**，不是让内容写得少。文章篇幅一律按 §6 的"越详细越好"执行。省调用次数的正确做法是**按章打包派 agent**（一次给 5–6 节的任务），而不是缩减每篇内容。

**★ 防 429 限流铁律（已多次踩坑，必须遵守）**

`AccountRateLimitExceeded`（HTTP 429）的根因是**瞬时请求量叠加**，不是总量。已验证的触发条件与对策：

| 触发行为 | 后果 | 正确做法 |
|---|---|---|
| **同时派 3 个 agent** | 请求量 ×3，几乎必然 429 | **一次最多派 2 个**，写作类任务**建议一次 1 个** |
| 逐个文件手动 Read + Edit | 调用次数爆炸 | 写一个临时 Python 脚本批量处理 |
| 多条独立命令分开发 | 每条都是一次往返 | 用 `;` 串成一条命令（如同步+提交+推送三合一） |
| 反复跑校验脚本确认 | 无谓往返 | 校验脚本一次跑完输出全部结果 |

**派 agent 的安全节奏**：
- 写作类（每篇 6000–10000 字，agent 内部读写频繁）：**一次 1 个 agent，写 3–5 节**
- 若确实要并行：**最多 2 个**，且两个任务的文件目录不重叠
- **绝不要 3 个及以上并行**——本项目已因此失败两次（2026-08-01、2026-08-02）

**遇到 429 后的正确处置**：
1. **不要立刻重试**，先用**一条**命令确认磁盘上的实际进度（很可能任务已完成，只是回执丢了）
2. 确认已完成的部分**立即提交推送**保住成果
3. 剩余部分**降低并发**（改成 1 个 agent）继续，不要原样重试

**★ 浏览器验证要一次取全数据（2026-08-07 又踩一次 429）**

用浏览器实测主题切换时，我做了导航 → 点击 → 两次 JS 求值 → 截图 → 读图，连续 6 次调用，撞了限流。**正确做法是一次 `browser_evaluate` 把所有要查的值一起返回**：

```javascript
// 一次拿全：主题状态 + 关键元素计算样式
const r = document.documentElement;
return JSON.stringify({
  dataTheme: r.getAttribute('data-theme'),
  bodyBg: getComputedStyle(document.body).backgroundColor,
  nodeTitleFill: getComputedStyle(document.querySelector('.node .node-title')).fill,
  nodeBgFill: getComputedStyle(document.querySelector('.node .node-bg')).fill,
  saved: localStorage.getItem('xhwy-theme')
});
```

另注意：**浏览器工具的 `browser_click` 可能被派发两次**（我点一次切换按钮，结果切过去又切回来，误判为「功能没生效」）。用 `browser_evaluate` 里直接 `el.click()` 更可控。

**★ 改 CSS / JS 前必须先核实标识符真实存在（2026-08-07 定，已犯过两次）**

我曾凭空写出项目里不存在的类名和变量，都是在核实环节才抓出来的：
- 写了 `.node .node-hit { stroke-width: 14px }` 想放大触摸区 —— **`node-hit` 这个类压根不存在**，节点其实是 `<rect class="node-bg">` 铺满整框、点击区域本来就够大
- 写了 `--ai` / `--network` / `--gui` / `--elec` 四个品牌色变量想在深色下提亮 —— **这四个变量不存在**，四篇颜色是各页面直接硬编码的（`#4a6d8c` 蓝 / `#556b3d` 绿 / `#8a5a7a` 紫 / `#a0662c` 铜）

**所以定下规则**：写任何 CSS 选择器或变量引用前，先 grep 确认它在 JS/HTML 里真实存在。
- 类名：搜 JS 里的 `class: 'xxx'` 与 HTML 里的 `class="xxx"`
- 变量：搜 `--xxx:` 的**定义处**，不能只看 `var(--xxx)` 的使用处

**改主题/样式后必跑的四项校验**（写成一个脚本一次输出）：
1. CSS 括号配平（**先去注释**再数 `{` `}`）
2. 暗色规则引用的每个类名都能在 JS / HTML / 浅色规则中找到
3. 暗色块定义的每个变量在浅色 `:root` 里都有对应（防止凭空造变量）
4. `color-scheme` 覆盖率达到全站页面数

**★ 推送验证规范（2026-08-07 补）**

- `hostfile_replace_entries: Operation not permitted` 是 SSH 更新 `known_hosts` 的**权限警告，与推送成败无关**，每次都会出现。
- **不要用 `git push -q`**——那会把 `main -> main` 的成功回显压掉，只剩这行警告，看着像失败（已因此让用户误以为没推上去）。
- 推送后**额外跑一条** `git ls-remote origin refs/heads/main`，与本地 `git log --oneline -n 1` 对比 commit hash 确认一致，再向用户汇报。

**★ 真机验证优先于模拟（2026-08-07 补）**

- 触摸交互、暗色模式这类**依赖设备与系统行为**的改动，让用户在真机上试**比在无头浏览器里派发合成事件可靠得多**。真机的多点触控事件顺序、浏览器手势拦截、系统强制反转行为都难以模拟。
- 改动是纯增量时（只新增事件监听、不动原有逻辑），风险低，可直接推送让用户验证。

## 常见 bug 记录

### Bug 1: 悬浮翻页岛不显示
**原因**: 新页面忘了引入 `float-pager.js` 或没有 `.pager` 元素。
**修复**: 检查页面底部是否有 `<script src="../../_shared/js/float-pager.js"></script>` 和 `<div class="pager">`。

### Bug 2: 知识树点击不能展开/收起
**原因**: `expandAndCollapse: true` 导致 ECharts 内部状态和数据不同步。
**修复**: 已改为 `expandAndCollapse: false` + 手动 toggle `collapsed`。

### Bug 3: 展开后 zoom 倒退
**原因**: `setOption` 时 ECharts 用旧数据重绘。
**修复**: 每次 `setOption` 都传入最新 `data`。

### Bug 4: 默认展开不生效
**原因**: `initialTreeDepth` 被数据中的 `collapsed: true` 覆盖。
**修复**: 渲染后强制执行 `expandToDepth(2)`。

### Bug 5: 认知树默认缩放太小
**原因**: SVG 有两层缩放叠加——`viewBox="0 0 worldW worldH"` 让 SVG 自动缩放内容，同时 `scene transform: scale(x)` 又缩放一次，两者叠加导致我的 scale 失效。
**修复**: SVG `viewBox` 改用**画布像素尺寸** (`0 0 clientW clientH`)，让 `scene transform` 完全掌控缩放。同时初始化用 `requestAnimationFrame × 2 + setTimeout 200ms 兜底`，确保 SVG 布局完成。

  ### 一、交互功能必须同时绑鼠标与触摸事件
  - **问题**：`assets/cognition-tree.js` 的拖拽只绑了 `mousedown`/`mousemove`/`mouseup`，缩放只绑了 `wheel`。**这四个事件在触摸屏上根本不触发**，所以手机上知识树完全不能拖也不能缩放。
  - **只改 JS 不够，CSS 必须配套**：`.tree-canvas` 要设 `touch-action: none`。不设的话，即便加了触摸事件，浏览器也会把单指拖动当成滚页面、双指捏合当成缩放整页，**手势会被系统抢走**。
  - 已实现：`touchstart` / `touchmove` / `touchend` / `touchcancel`，支持**单指拖动、双指捏合缩放、双击缩放**。`zoom()` 已改为支持传入焦点坐标（`zoom(delta, cx, cy)`），让缩放围绕手指中心而非画布原点。
  - **双指缩放要相对起始状态整体计算**（记下 `pinch.d` 与 `pinch.s`，用 `pinch.s * (nd / pinch.d)` 算目标值），**不要逐帧累乘**，否则会累积误差漂移。
  - **手指按在节点上时要跳过平移逻辑**（`if (inNode(e.target)) { touchDrag = null; return; }`），否则会吞掉节点自己的 `click`，导致点节点没反应。
  - **SVG 元素的 `closest()` 在个别旧版移动浏览器上不可靠**，已改为手写 `inNode()` 沿 `parentNode` 向上遍历并用 `/\bnode\b/` 匹配 `class` 属性。注意 SVG 元素要用 `getAttribute('class')` 而不是 `classList`。
  - **移动端触摸目标不小于 40px**。原工具栏按钮 `padding: 5px 10px` + 11px 字体只有约 22px 高，手机上很难点准，已提到 `min-height: 40px`。
  - 加 `@media (hover: none)` 关掉移动端的 hover 粘滞态。

  ### 二、站点原本没有暗色模式，这是知识树文字看不见的真正原因
  - **根因链条要记住**：`theme.css` 只有一套浅色变量 → 用户看到的「黑色模式」来自**浏览器/系统的强制反转** → **强制反转能改 CSS 背景，但改不了 SVG 里硬编码的 `fill` 值** → 知识树节点文字写死 `#2b2a26`（深墨）与 `#8a8579`（灰），于是深色字压深色底，看不见。
  - **必须加 `<meta name="color-scheme" content="light dark">`**。这是关键一步：声明后浏览器知道站点自己支持深色，就不再强制反转，避免「双重处理」把颜色搞乱。已批量补到全站 98 个 HTML（脚本幂等，插在 `viewport` 之后）。**以后新建页面必须带这一行**。
  - **暗色规则只覆盖颜色变量，绝不动版式与字体**。已在 `theme.css` 的 `:root` 之后加 `@media (prefers-color-scheme: dark)` 覆盖 11 个颜色变量，这样全站页面自动跟随，不用逐页改。
  - 底色用 `#1c1e1b` / `#23261f` / `#282b24` 这类**带暖调的深色而非纯黑**，保留原本的纸感。
  - 额外需要单独处理的四处（纯靠变量覆盖不到）：① `pre`/`code` 底色；② 表格斑马纹（深色下要反向，用 `rgba(255,255,255,.022)`）；③ `mark`/`mark.key` 高亮句（浅色下的淡黄底在深色下太刺眼，改低饱和暖底）；④ `img`/`svg image` 加 `filter: brightness(.92)` 消除发光感。
  - `cognition-tree.css` 需要独立的暗色块，覆盖 `.node-bg` / `.node-title` / `.node-meta` / `.edge` / `.spec-dot` / `.branch-dot` / 详情面板全套。**注意 `.edge` 连线**——浅底上的深色线在深底上同样会消失，很容易漏掉。
  - **状态圆点的白色描边（`stroke: #ffffff`）在深色节点上会很扎眼**，要改成接近底色的深色描边；而「可跳转」的深绿 `#556b3d` 在深底上看不出，要提亮到 `#93b06f` 一类。

  ### 三、★ 一条硬教训：改 CSS 前必须先核实类名和变量是否真实存在
  - 我这次犯过两个「凭空创造」的错误，都在核实环节被抓出来：
    1. 写了 `.node .node-hit { stroke-width: 14px }` 想放大触摸区 —— **`node-hit` 这个类在项目里压根不存在**，节点其实是 `<rect class="node-bg">` 铺满整框、点击区域本来就够大。
    2. 写了 `--ai` / `--network` / `--gui` / `--elec` 四个品牌色变量想在深色下提亮 —— **这四个变量不存在**，四篇的颜色是各页面直接硬编码的（`#4a6d8c` 蓝、`#556b3d` 绿、`#8a5a7a` 紫、`#a0662c` 铜）。
  - **所以定下规则**：写任何 CSS 选择器或变量引用前，先用 grep 确认它在 JS/HTML 里真实存在。具体做法：
    - 类名：搜 JS 里的 `class: 'xxx'` 与 HTML 里的 `class="xxx"`
    - 变量：搜 `--xxx:` 的定义处，不能只看 `var(--xxx)` 的使用处
  - **已建立校验脚本的检查项**（以后改主题必跑）：① CSS 括号配平（去注释后数 `{` `}`）；② 暗色规则引用的每个类名都能在 JS/HTML/浅色规则中找到；③ 暗色块定义的每个变量在浅色 `:root` 里都有对应；④ `color-scheme` 覆盖率 98/98。

  ### 四、验证策略：真机优先于模拟
  - 触摸交互这类改动，**让用户在真机上试比我在无头浏览器里派发合成事件可靠得多**。真机的多点触控事件顺序、浏览器手势拦截行为都难以模拟。
  - 改动是纯增量时（只新增触摸事件、不动原有鼠标逻辑），风险低，可以直接推送让用户验证，但**必须明确告诉用户要留意哪几点**（我这次列了：双指缩放会不会跳、点节点还灵不灵、页面还能不能正常上下滚）。
  - `hostfile_replace_entries: Operation not permitted` 是 SSH 更新 `known_hosts` 的权限警告，**与推送成败无关**，每次都会出现。**不要用 `git push -q`**，那会把 `main -> main` 的成功回显压掉，只剩这行警告，看着像失败。推送后应额外跑 `git ls-remote origin refs/heads/main` 与本地 HEAD 对比确认。
