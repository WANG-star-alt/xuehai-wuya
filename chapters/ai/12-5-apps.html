§ 12.5 · Section

应用与工具层

TRAE、Cursor、GitHub Copilot、Midjourney · 你每天花的钱去哪了

终于走到这张地图的最上面一层——你每天真正打开、真正付钱的那些产品。前面四节讲的芯片、模型、开源工具，你可能一辈子不会直接碰；但这一节讲的东西，你此刻很可能正在用其中一个。本节重点讲 TRAE，因为它的计费体系有一个特别值得摊开的现象：中国站和国际站是两套完全不同的计费制度，甚至连产品有几种模式，两边官方公告写的都不一样。这是本章第二处「官方内部不一致」。第三处则在 GitHub Copilot 与 Anthropic 官方之间：Copilot 的套餐页列出了 Claude Opus 4.8，而 Anthropic 自家官方总览当天最高只列到 4.7。本节会把这两处双边原文都摆出来，并讲清「第三方平台清单」和「厂商官方文档」为什么不能互相替代。所有内容截至 2026 年 8 月 8 日。

生活场景
🎫 同一家健身房的两种会员卡

假设有一家连锁健身房，在国内和国外都开了店。你要办卡，会发现两边的规则完全不是一套。

国内店：卖「点数卡」。99 元买 4000 点，每上一节课扣多少点，价目表贴在墙上。你关心的是「我还剩多少点」。另外店里还搞活动：某两位教练的课打二五折。

国外店：卖「额度卡」。10 美元的月费里含 20 美元的「使用额度」，用掉多少直接按钱扣。你关心的是「我还剩多少钱」。

这时候如果有人问你「这家健身房的会员多少钱、能上多少课」，你会发现这个问题没法用一句话回答——因为两边根本不是一套计量单位。说「99 元能上 4000 点的课」在国外店毫无意义，说「10 美元含 20 美元额度」在国内店也对不上。

而更微妙的是：国内店的宣传单上写「本店有力量、有氧、康复三个训练区」，国外店的同一份宣传单写的是「两个区：力量和有氧」。说白了——同一个品牌，两边的产品形态和计价方式都不一样，这不是谁在骗人，是两个市场各自演化的结果。

→ 这就是 TRAE 的真实情况，两边原文都在下面。本节的原则和前面一样：两套都写，标清各自出处，绝不混用。

先说清「应用与工具层」是什么位置

回到章总览那个牛肉面的四层结构：芯片是种麦子的，模型公司是磨面粉的，开源生态是菜市场，而这一节讲的是面馆师傅。

这一层有三个共同特征，理解了它们你就能看懂这一层所有产品的逻辑：

  • 它们大多不自己造模型它们买别人的模型，加上自己的界面、流程、上下文管理。说白了：面粉是买的，本事在调汤和火候。所以「这个工具用的是什么模型」往往是可选、可换的。
  • 它们的价值在「把模型接进你的工作流」一个模型再强，你也不会愿意每次复制粘贴代码到网页去问。工具层做的就是把这个来回省掉。相当于面馆的价值不在于有面粉，而在于你走进去坐下就有一碗热的。
  • 它们的计费最复杂，因为要在中间赚差价上游是按 token 收费的（§12.2、§12.3 那些价格），下游你希望按月付固定的钱。这中间的换算，就是本节所有计费复杂性的根源。

第三条值得多说一句，因为它解释了「为什么这些产品的定价页都这么难懂」。

用手机套餐打比方：运营商的成本是按流量、按分钟发生的，但你希望买一个「99 元包月」。于是就出现了各种「含 30GB 流量、超出后每 GB 5 元、闲时流量不计入」这类复杂规则——它们全都是在「上游按量、下游包月」这个矛盾之间做的调和。AI 工具的定价页复杂，原因完全一样。

TRAE 是什么：官方怎么定位自己

先看官方定位。docs.trae.cn 中文原文：

「TraeCode 是一款深度融合 AI 能力的开发工具，提供从代码编写、
项目理解、调试运行到变更管理的完整开发体验。你可以像使用传统 IDE
一样掌控每一步，也可以把复杂任务交给 AI 智能体规划和执行。」

英文站同一页：

"TraeCode is a development tool deeply integrated with AI
capabilities. It provides a complete development experience that
spans coding, project understanding, debugging and running, and
change management."

这两段在定位上是一致的——中文多了后半句关于「交给 AI 智能体」的补充，但核心表述对得上。差异出现在下一小节要讲的模式数和计费上。

官方对 TraeCode 双模式的表述（中文原文）：

「IDE 模式：保留熟悉的编辑器、终端、调试、插件、源代码管理等工作流……
SOLO 模式：以 AI 为主导，通过自然语言描述或语音的方式输入需求后，
AI 会自动规划任务，并推进代码生成、测试、预览和变更总结等步骤。」

这两种模式的差别，正好对应 §11.1 讲过的那条分界线。回忆一下那一节的 Copilot 与 Agent 对照表：

模式官方描述的要点谁在开车§11.1 的对应概念生活类比
IDE 模式保留编辑器、终端、调试、插件、源代码管理等工作流你，AI 在旁边帮忙偏 Copilot（副驾驶）你自己下厨，旁边有个帮手递东西
SOLO 模式以 AI 为主导，自然语言或语音输入需求，AI 自动规划任务并推进生成、测试、预览、变更总结AI，你说需求偏 Agent（智能体）请厨师上门，你只说「今晚想吃红烧肉」

注意 SOLO 模式描述里那个词序：「自动规划任务，并推进代码生成、测试、预览和变更总结」。这是一个完整的循环，正是 §11.1 里定义 Agent 的第四个特征。说白了：它不是「你说一句它写一段」，而是「你说一句，它自己排出好几步然后一步步做完」。

★ 本章第二处官方不一致：中英文站的模式数不同

这一处非常干净——同一条产品公告，中英文站写的模式数量不一样。双边原文照抄：

中文站公告原文：

「TraeWork 客户端上线，提供网页版、桌面版和移动版三种客户端，
并设有为不同用户群体设计的 Work、Code 与 Design 三种模式。」

英文站同一条公告原文：

"It features two modes—Work and Code—designed for different user
groups."

摆到表里对比：

中文站英文站
模式数三种两种
模式名Work、Code、DesignWork、Code
客户端形态网页版、桌面版、移动版三种该句未提

差异点很明确：中文站多一个 Design 模式。

本节不判断哪个是对的，因为我们没有依据做这个判断。但可以指出这个差异本身的可靠度是高的——双边原文都是同一天从各自官方站点抄下来的。

那这个差异可能是怎么来的？下面是推断而非结论，请这么读：常见的原因有三种，都很平常。

  • 可能一 · 功能分区域上线Design 模式可能先在中国区上线，国际区还没开。相当于连锁店的新品先在一个城市试，成了再推全国。
  • 可能二 · 文案更新有先后中文站更新了，英文站的这条公告还是旧版。这和 §12.2 里 OpenAI 那三个页面的情况同源。
  • 可能三 · 两地产品策略本来就不同这一点被下一小节的计费差异强烈支持——既然连计费制度都是两套，产品形态不同也就顺理成章。

但请注意：以上三条全是推断。官方没有对这个差异做过任何说明。说白了：我能确认的只有「两边写得不一样」这件事，剩下的都是我在猜。这条界限必须画清楚。

★ TRAE 计费：两套完全不同的体系，绝不能混用

这是本节最实用的一段，尤其如果你正在付钱用它。中国站与国际站不只是价格不同，是整个计量单位不同。

先看中国站：积分制，人民币。官方原文对制度的表述：

「TRAE 采用以积分为核心的计费体系，并提供多档付费会员套餐。
TRAE 会员可享每月专属积分、高峰期优先使用、更多云端任务并行额度，
并获得 Seed 系列模型 2.5 折计费福利。」

这张表里有四个细节，不看仔细容易吃亏：

  • Lite 的积分是「Work 专属」而其他三档是「通用」。这意味着 Lite 档的 2000 积分不能用在 Code 上。如果你主要用 TraeCode 写代码，Lite 档对你是无效的。这一条最容易看漏。
  • 积分不是线性涨的¥99 给 4000 分，¥239 给 12000 分，¥699 给 40000 分。算一下每分的价格：Pro 约 ¥0.0248/分，Pro+ 约 ¥0.0199/分，Ultra 约 ¥0.0175/分。说白了：买得越多单价越便宜，相当于超市里大包装比小包装划算。
  • 「31 自然日」不是「一个月」这个措辞很精确。2 月只有 28 天，而它给你 31 天；而按自然日算意味着从你付款那天起算，不是按日历月。相当于健身房的卡写「31 天有效」而不是「一个月」——后者会引出「大月小月怎么算」的纠纷。
  • 「新模型优先」只有 Ultra 有前三档这一栏都是「/」。这是一个典型的差异化设计——不是给你更多量，而是给你更早的时间。相当于演唱会的粉丝会员，票价一样但能先抢票。

trae.cn 首页当日还有一条横幅：「新用户赠送 4500 积分」。把它跟表对一下会发现一个有意思的事：4500 积分比 Pro 档一个月的 4000 积分还多。这是相当积极的拉新手段——说白了：先让你把整个月的量用一遍，用顺手了再谈付钱。

现在看国际站：Dollar Usage 制，美元。这是完全不同的一套东西。官方 FAQ 原文：

"All AI requests are billed based on the number of tokens processed.
TRAE converts the token cost into Dollar Usage, which is deducted
from your monthly balance."

翻译：「所有 AI 请求按处理的 token 数计费。TRAE 把 token 成本换算成 Dollar Usage（美元用量），从你的月度余额中扣除。」

请注意这句话的关键：它不是「积分」，是直接按美元金额记账的。这就把 §12.2、§12.3 那些 token 价格和你的账单直接挂上了钩。

这个「越高档越划算」的结构和中国站的积分单价递减是同一个逻辑——相当于批发市场的量价关系：买一箱和买一车的单价不一样。两套体系表面完全不同，底层的商业设计其实是一致的。

那这两套体系能不能换算成同一个数？不能，而且不该试。理由有三：

  • 一 · 计量单位不同积分 vs 美元金额。官方没有公布积分与美元的换算率，任何换算都是自己编的。
  • 二 · 覆盖的产品不同中国站 Lite 仅限 TraeWork；国际站 Free 档就标明 SOLO included。连「一档包含什么」的划分方式都不一样。
  • 三 · 附加权益不同中国站有 Seed 系列 2.5 折这个专属福利，国际站表里没有对应项；国际站有 Autocompletion 5000/月 这样的具体额度，中国站表里没有对应项。拿两边的价格数字直接比较，会得出毫无意义的结论。

用一个生活场景收这一段：你不能问「这家店的会员卡是 99 元还是 10 美元哪个划算」——因为这是两家店，卖的东西不完全一样，计量方式也不一样。唯一有意义的问题是：你在哪个站注册的、你要用哪个产品、你的用量大概多少。

Analogy · 面馆师傅的进货单

工具层的商业模式，用一张面馆的进货单就能讲透，而且能顺带解释「为什么这些产品要支持那么多模型」。

你开了一家面馆。你的成本结构是这样的：面粉按斤买（上游按量计费），而客人按碗付钱（下游按次或包月）。这中间你要做三件事：

第一，你得同时跟好几家面粉厂进货。一家断货了、涨价了、质量波动了，你不能就此关门。所以你的储藏室里永远备着两三个牌子的面粉。

第二，你得根据菜品挑面粉。做手擀面用高筋粉，做疙瘩汤用普通粉——不是越贵越好，是对得上才好。而且客人只关心那碗面好不好吃，压根不关心你用的哪家面粉。

第三，你要把「按斤」的成本换算成「按碗」的定价。而且要留出余量，因为有人吃一碗、有人吃两碗加两个蛋。这个换算就是所有会员制、点数制、额度制的来源。

把这三件事对回 TRAE，你会发现它一件不差：第一件对应它的内置模型清单里有 MiniMax、GLM、DeepSeek、Kimi、Qwen 好几家（下面就讲）；第二件对应它允许你切换模型、也允许你接自定义模型；第三件对应中国站的积分和国际站的 Dollar Usage。

而这个类比还能解释另一件事：为什么工具层的公司容易活得辛苦。面馆的面粉是别人的、灶台是租的、客人对价格敏感、隔壁随时能再开一家。它真正的护城河只有一样——你走进去坐下就有一碗热的这份「顺手」。这就是为什么这一层的产品拼命打磨体验和工作流集成，因为除此以外它没什么别人拿不走的东西。

这张表有三个观察点，每一个都能说明一件事：

观察一：六家厂商同时在列，其中五家是外部的。字节自己造模型，但内置清单里的大多数不是自家的。这印证了前面那个进货单的类比——面馆同时跟好几家面粉厂进货。而对你来说，这意味着换模型的成本被压到了一个下拉菜单。

观察二：智谱有三个版本同时在列（GLM-5.2、5.1、5）。为什么不只留最新的？因为不同版本的行为不一样，有人的工作流已经调好了配 5.1，换成 5.2 反而不顺手。相当于面馆同时备着新面粉和老面粉，因为有老客人就爱老那口。说白了：在工具层，稳定性有时比先进性更值钱。

观察三：这份清单里的型号名比 §12.3 更新。对比一下：§12.3 讲智谱时官方文档给的是 GLM-4.6，这里已经到 GLM-5.2；§12.3 讲 Kimi 时是 K2.5，这里已经到 K3 与 K2.7-Code。这说明「查一个模型的最新型号，有时在集成它的第三方平台上能看到更新的」。但请注意——这不能反过来当成厂商官方型号的依据（下面讲 Copilot 时会详细说这个道理）。

除了内置模型，官方还说明支持自定义模型：「除内置模型外，TRAE 还支持接入自定义模型」，分「模型服务商」与「自定义配置」两种方式，后者需要配置API 格式、请求地址、模型 ID 和鉴权信息。

这四项要配的东西，正好对应 §12.2、§12.3 里我们抄下来的那些数据：

  • API 格式OpenAI 格式还是 Anthropic 格式。回忆 §12.3 里 DeepSeek 给了两个 Base URL 分别对应这两种格式——现在你知道那个设计是给谁用的了。
  • 请求地址就是 §12.3 那些 Base URL，比如 https://api.deepseek.com。
  • 模型 ID§12.2 那套六步法的第三步就是「抄下模型 ID 而不是产品名」——这里填的就是 ID。
  • 鉴权信息你的 API 密钥。相当于进小区要刷的那张钥匙卡。

看到这里，前面几节那些看似枯燥的对照表就有了实际用途——它们不是给你背的，是给你填表单用的。

另外两项官方目录级证据（出处 docs.trae.cn/llms.txt）：文档目录中包含「工具与插件 / 模型上下文协议(MCP) / MCP 概览」与「添加 MCP Server」，以及「AI 编程核心 / 技能（Skill）」。官方对技能的描述是：技能「通过 SKILL.md 定义管理，具有结构化、按需加载特点」。

MCP 就是 §11.6 讲过的那个「工具界的 USB-C」。它出现在 TRAE 官方文档目录里，意味着你可以按 §11.6 讲的那套办法给它接外部工具。而「按需加载」这个描述值得留意——它说的是技能不会一直占着上下文，用到才加载。相当于厨房里的调料不全摊在案板上，需要哪个再从架子上取哪个（回忆 §11.6 关于上下文预算的讨论）。

这两项的可靠度标注为目录级证据——说白了：我们确认了官方文档里有这些章节，但没有逐页读完正文。所以只写「有这个能力」，不写具体用法细节。

用倍数而不用绝对值来标注额度，是这一层普遍的做法，值得单独说一句为什么。因为「Agent requests」这个东西本身不好用绝对数说明——一次请求消耗多少，取决于用哪个模型、任务多复杂、要跑几轮。说白了：官方自己也没法承诺「你能跑 500 次」，所以只能说「是 Pro 的三倍」。相当于汽车的续航标「比上一代多 30%」而不标绝对公里数——因为绝对值取决于你怎么开。

"Every plan includes a set amount of model usage. On-demand usage
allows you to continue using models after your included amount is

「billed in arrears」（后付费 / 欠账结算）这个词组要当场翻译清楚，因为它涉及钱。意思是：你先用，账后结。相当于手机套餐的流量超了不断网，而是按超出量算钱，下个月账单上体现。好处是不会突然干不了活，风险是账单可能超出预期。

"Cursor subscriptions are only sold directly through cursor.com.

翻译：「Cursor 订阅仅通过 cursor.com 直接销售。我们不授权任何转售商或第三方销售者。」

一个官方页面专门写这句话，通常说明外面确实有人在转卖。这条信息对读者是有实际价值的：看到第三方渠道的低价订阅，按官方口径那是未经授权的。相当于演唱会官网写着「本场票务仅通过官方平台发售，不设代理」——这句话本身就是一条提醒。

用超市和厂家的关系打比方，这件事就非常清楚了。某个牌子的酸奶出了新口味，超市的货架上摆出来了，而厂家官网的产品页还没更新。这两件事都是真的，也都不奇怪——因为货架的更新速度和官网文案的更新速度本来就不同步。

但这里有个更要紧的道理：如果你想知道「这款酸奶的配料表和保质期」，你必须看厂家的说明，不能看超市的价签。反过来，如果你想知道「今天在这家超市能买到哪些口味」，那超市的货架才是权威，厂家官网帮不了你。

所以正确的引用规则很清晰：

  • 要引用模型规格、上下文、官方定价必须看厂商官方文档。Copilot 的清单里没有这些信息，也不该有。
  • 要说明「在某平台上能用到哪些模型」必须看那个平台的官方页面。厂商文档不会告诉你 Copilot 里有什么。
  • 两者出现型号差异时如实并列，标明各自出处与日期，不合并成一句话。本节就是这么做的。
  • 绝对不能做的事拿 Copilot 的清单当依据说「Anthropic 已发布 Opus 4.8」。说白了：超市摆了新口味，不等于你可以替厂家宣布产品上市。这中间隔着一层，跨过去就是编造。

顺带说一个同类现象：前面 TRAE 内置模型清单里 GLM 已到 5.2、Kimi 已到 K3，而 §12.3 引用的厂商官方文档只到 GLM-4.6 和 K2.5。这是完全同一类型的差异，处理办法也完全一样。

Midjourney：一个把「版本更替」写得极清楚的例子

换个方向，看一个图像生成产品。Midjourney 的官方版本文档（docs.midjourney.com/hc/en-us/articles/32199405667853-Version）是本章遇到的写得最清楚的一份版本记录，值得单独学。

官方原文（截至 2026 年 8 月 8 日）：

"The current default Midjourney version is V8.2."

"V8.2 released as the default version on July 24, 2026. V8.2 is an
update focused on aesthetics, image quality, and Personalization."

"V8.1 released on April 14, 2026, and was the default version from
June 10 to July 23, 2026."

"V8.0 was an early access alpha version that launched on March 17,
2026 and was available on the Midjourney Alpha website until
July 24, 2026. Images generated in V8.0 are still available in your
website gallery, but the version is no longer available for use."

这段文档为什么是范本？因为它把四件事都交代清楚了：

它交代的事具体内容为什么重要
当前默认是哪个V8.2直接回答了最常见的那个问题，不用你猜
每个版本的发布日V8.2 是 2026-07-24；V8.1 是 2026-04-14；V8.0 是 2026-03-17精确到日，你能自己判断新鲜度
「担任默认版本」的起止区间V8.1 从 2026-06-10 到 2026-07-23 是默认这一条最难得——它说明「发布日」和「成为默认」是两个不同的日期，中间隔了近两个月
下线之后旧内容怎么办V8.0 生成的图仍在你的画廊里，但该版本本身不再可用明确区分了「不能再用它生成」和「以前生成的还在」

第三行那个细节值得多说一句，因为它是这一层产品的通用规律。V8.1 在 4 月 14 日发布，但要到 6 月 10 日才成为默认版本。用餐厅上新菜打比方：新菜 4 月就能点了（写在「新品试吃」那一页），但要到 6 月才被印到正式菜单第一页、成为服务员默认推荐的那道。说白了：「能用了」和「成了默认」是两个阶段。

另外还有一条关于成本的官方说明（V8.1 的 HD 特性，HD 为 2048px）：

"HD costs 1.3 minutes of GPU time, compared to SD which costs 0.8
minutes of GPU time."

翻译：「HD 消耗 1.3 分钟的 GPU 时间，相比之下 SD 消耗 0.8 分钟。」

注意它的计价单位——不是「张」，是「GPU 时间」。这个设计非常诚实地反映了成本本质：生成一张图真正花的是机器时间，而不是「一张」这个抽象单位。

用打印店打比方：老板不按「几张」收钱，而按「机器转了几分钟」收钱——因为一张密密麻麻的图纸和一张只有几行字的纸，机器耗的时间差很多。而 1.3 除以 0.8 约等于 1.6，也就是说出 HD 图的成本大约是 SD 的一倍半多。这个比例你可以直接拿来估算自己的用量。

版本切换的参数官方给的是 --version 或简写 --v。

把三处「官方不一致」放在一起看

本章从头到尾出现了三处官方内部不一致，全部在这一节收拢一遍。因为它们虽然长得不一样，但可以归成两种类型，而这两种类型的处理办法不同。

矛盾双方差异内容类型
第一处 · §12.2OpenAI 的 platform 域 / developers 域 / 定价页flagship 一个说 gpt-5.5、一个说 GPT-5.6 Sol；定价页未列 5.6同一主体内部
第二处 · §12.5TRAE 中文站 / 英文站模式数三种 vs 两种；计费体系一套积分制、一套 Dollar Usage 制同一主体内部

前两处是「同一主体内部不一致」，处理办法是：并列双边原文、标出各自入口与日期、明确指出这是同一家公司的不同页面。不挑一个当真相，因为你没有依据挑。

第三处是「不同主体之间不一致」，处理办法不同：要先分清两个信源各自的身份和职责范围，然后按「谁该回答这个问题」来定用哪个。说白了：问配料表看厂家，问今天有什么货看超市。这不是矛盾，是分工。

还有一类现象本章也遇到多次，虽然不算「矛盾」，但同属新鲜度问题：

  • 过期公告仍在挂着DeepSeek 那条「2026 年 7 月 24 日弃用」的脚注，在 8 月 8 日已经过期（§12.3）
  • 官方自承文档过期Kimi 直接写「This documentation is outdated」（§12.3）
  • 清单滞后大半年火山方舟那份清单自标 2025.12.10（§12.3）
  • 未标更新日期Qwen 文档站那一页（§12.3）
  • 发布了但不是所有人能用Copilot 的「We're gradually enabling new sign-ups」；Anthropic 的 Claude Mythos Preview 仅限受邀（§12.2）
  • 已发布但已关停Google 官方页面上 Gemini 3 Pro Preview 标 (Shut down)（§12.2）

把这一整份清单摆出来，你会得到本章最实用的一个判断：在这个行业里，「官方文档完全准确且内部一致」是特例，不是常态。

用一个开会的场景收这个道理：一家几千人的公司开全员大会，各部门的汇报里总会有几处对不上——不是有人撒谎，是信息在不同部门里以不同速度流动。本质上就是：组织越大、迭代越快，对外说法的不同步就越难避免。你能做的不是指望它们一致，而是养成「至少看两个入口 + 记查询日期」的习惯。

常见误解澄清

误解一：「这些 AI 编程工具都差不多，选便宜的就行。」

价格没法这么比，因为它们的计量单位根本不同：TRAE 中国站用积分、TRAE 国际站用 Dollar Usage、Cursor 用 requests 倍数、Copilot 用 credits 加 Flex allotment。说白了：四把不同的尺子，量出来的数没法放在一起排序。能比的只有一件事——照你自己的实际用量，各家一个月扣完之后你还剩多少。

误解二：「工具用的什么模型不重要，反正都能写代码。」

它确实不像你想的那么重要（因为大多支持切换），但也不是完全不重要。回看 TRAE 中国站那条 Seed 系列 2.5 折的福利、Copilot Pro+ 才「Access to premium models, including Opus」、TRAE 内置清单里两个 Doubao-Seed-2.1 型号「仅限优速通 Express 和速通 Ultra 用户」——这三条都说明：你能用哪些模型，是跟档位绑定的。

误解三：「Copilot 的清单里有 Opus 4.8，所以 Anthropic 已经发布了 4.8。」

这是本节最想纠正的一条。第三方平台的清单不能当厂商官方发布的依据。超市摆了新口味，不等于你可以替厂家宣布产品上市。正确的说法是：「截至 2026 年 8 月 8 日，GitHub Copilot 套餐页列出了 Claude Opus 4.8；而 Anthropic 官方模型总览当天最高列到 Opus 4.7。」两句话都说，都标日期。

误解四：「TRAE 中文站说三种模式，英文站说两种，肯定有一边写错了。」

「有一边写错」是一种可能，但不是唯一可能——功能分区域上线、文案更新有先后、两地产品策略本就不同，都能解释这个差异。而本节能确认的只有「两边写得不一样」这一件事，其余全是推断。把推断当结论写出去，是这一节反复在防的那个错误。

误解五：「工具层技术含量低，就是套个壳。」

这个说法忽略了前面进货单类比里的第三件事：把「按 token 的成本」换算成「按月的定价」，而且不能亏本、又不能贵到没人买。另外还有上下文管理、多轮任务的规划、变更的追踪与回滚——§11.1 讲过的那句「errors compound（错误会累积）」，正是这一层每天要对付的问题。相当于说面馆「就是把面煮一煮」——技术上没错，但没解释为什么有的店排队有的店关门。

误解六：「查不到 Perplexity 和 Midjourney 的价格，说明这本书不够全。」

这个批评本节接受一半。不全是事实——本章明确列出了 8 处未取得。但「不全」和「编造」之间，我们选择不全。Midjourney 定价页返回人机验证页、Perplexity 五个官方地址全部失败，这些都在正文里写明了地址与结果，你可以自己去补。说白了：一份研究能被人接着查下去，比它看起来完整更重要。

Recap · 这一节收束

一、工具层的位置与商业逻辑。它们大多不自己造模型，价值在「把模型接进你的工作流」，而所有计费复杂性都来自同一个矛盾——上游按 token 计量，下游希望包月。进货单类比：同时跟多家面粉厂进货、按菜品挑面粉、把按斤的成本换算成按碗的价。

二、★ TRAE 的两套计费绝不能混用。中国站是积分制人民币（Lite ¥49 / Pro ¥99 / Pro+ ¥239 / Ultra ¥699，对应 2000 / 4000 / 12000 / 40000 积分，有效期均为 31 自然日，Seed-2.1-Turbo 与 Seed-Code 计费 2.5 折）；国际站是Dollar Usage 制美元（Free / Lite $3 / Pro $10 / Pro+ $30 / Ultra $100，含用量 $5 / $20 / $90 / $400）。官方未公布积分与美元的换算率，任何换算都是自己编的。另注意中国站 Lite 的积分是「Work 专属」，不能用于 Code。

三、★ 中英文站的模式数不一致。中文站：「Work、Code 与 Design 三种模式」；英文站：「two modes—Work and Code」。差异本身可靠度高（双边原文同日抄录），成因则一律是推断，官方未做说明。

四、★ 第三方平台清单 ≠ 厂商官方文档。Copilot 列 Opus 4.8，Anthropic 官方最高 4.7；TRAE 内置清单已到 GLM-5.2、Kimi-K3，而 §12.3 的厂商文档只到 GLM-4.6、K2.5。问规格看厂家，问「这里有什么货」看平台——这不是矛盾，是分工。

五、几个值得学的官方措辞。Cursor 的「billed in arrears」（后付费，先用后结）与「不授权任何转售商」；Copilot 的「We're gradually enabling new sign-ups」（已发布不等于你能注册）；Midjourney 把「发布日」与「成为默认的起止区间」分开写，并说明 V8.0 下线后旧图仍在画廊。Midjourney 的计价单位是 GPU 时间而非张数（HD 1.3 分钟 vs SD 0.8 分钟，约一倍半）。

六、本节的留白清单（诚实交代）：TraeCode CLI 的形态、安装方式与能力全部未取得（中英文站七个地址全部失败，官方 llms.txt 索引当日未列 cli 章节；自媒体内容一律不采用）；Cursor 的 Pro+ / Ultra 具体价格未取得（官方页只给倍数不给数字）；Midjourney 定价未取得（返回人机验证页）；Perplexity 的定价与型号整条未取得（五个官方地址全部失败，故一字不写）；TRAE 的 MCP 与 Skill 仅有目录级证据，未读正文细节。所有内容的查询日期为截至 2026 年 8 月 8 日。
